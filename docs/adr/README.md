# Architecture decision records

These are the Phase 0 decisions from the [roadmap](../roadmap.md) (task 0.5). Each record states the context, the decision, and what follows from it. When a decision changes, add a new record that supersedes the old one rather than rewriting it.

| [0018](0018-the-port-fixes-bugs-and-sets-enhancements.md) | The port fixes the original's bugs outright and puts enhancements behind settings; there's no fidelity toggle | Accepted, refined by [0023](0023-the-core-is-handed-its-settings-each-tick.md), added to for content by [0029](0029-content-fixes-wait-for-a-bugfix-mod.md) |
| [0019](0019-how-the-core-tells-the-views.md) | How the core tells the views what changed: host calls and cues, events for lifecycle, polling for continuous state, returned endings | Accepted |
| [0020](0020-one-effect-vocabulary.md) | One effect vocabulary for spells, potions and enchantments: records list effects of types the core implements, with Lua a reserved type | Accepted, partly superseded by [0021](0021-instant-effects-land-in-one-place.md) |
| [0021](0021-instant-effects-land-in-one-place.md) | Instant effects land in one place for any spell, potion or flask; a potion record says how it's used, and a spell record whether it's an area | Accepted |
| [0022](0022-views-library.md) | The runtime and the editor share a views library, `HBHT.Views`, in place of the editor linking the runtime's files; code flows from the core to the views to the runtime to the editor | Accepted |
| [0023](0023-the-core-is-handed-its-settings-each-tick.md) | The core is handed what it needs of the settings each tick, an immutable record made from the player's with the command line's over them; nothing in the core reads `Settings` | Accepted |
| [0024](0024-the-options-are-pages-by-kind.md) | The options are pages by kind (Audio, Video, Enhancements), in Title Case, and the sky's placement is off the menu | Accepted |
| [0025](0025-chunks-load-off-the-main-thread.md) | Chunks load off the main thread where it can't change the game: what changes it stays on the main thread, reading ahead and building nodes outside the tree go to one builder thread, and the main thread never waits on it | Accepted |
| [0026](0026-controls-are-bound-by-situation.md) | Controls are listed by what the player does in each situation, bound per device in the core, with conflicts checked within a situation and the essential controls never left unbound | Accepted, mouse look superseded by [0036](0036-the-mouse-turns-the-camera-by-dragging.md) |
| [0027](0027-conversations-take-the-menus-controls.md) | Cut-scenes and conversations take the menus' cursor, Accept, Back and Close Menu, and have no controls of their own | Accepted |
| [0028](0028-the-project-is-hbht.md) | The project is HBHT: the code is `HBHT.*`, the editor is `HBHT.Editor`, the tool is `hbht` and the data folder is `HBHT`; "aidyn" stays for the game's names and the imported data (record IDs, `aidyn.base`) | Superseded by [0030](0030-the-project-is-aidyn-renewed.md) |
| [0029](0029-content-fixes-wait-for-a-bugfix-mod.md) | The base import fixes only content that breaks the game; other content fixes wait for a bugfix mod | Accepted, names amended by [0037](0037-the-rom-plugin-base-plugins-and-mods.md) |
| [0030](0030-the-project-is-aidyn-renewed.md) | The project is Aidyn Renewed, a fork of HBHT: the code is `AidynRenewed.*`, the tool is `aidyn-renewed`, the data folder is `AidynRenewed`, the packages are the fork's own; no third-party decompilation's names are cited, and the citations 0015 kept as credit are removed | Accepted, partly superseded by [0033](0033-the-project-is-aidyn-chronicles-enhanced.md) |
| [0031](0031-a-data-edit-of-1.0-imports.md) | A ROM hack of NA 1.0 that changed only bytes of the tables the layout places imports as 1.0 under its own hash; the importer's name checks against 1.0's data apply to 1.0 alone | Accepted, its import of a data edit superseded by [0038](0038-only-the-unmodified-1.0-rom-imports.md) |
| [0032](0032-rechronicled-is-read-for-its-findings.md) | Aidyn ReChronicled is cloned beside the project without its submodules and read for its findings and designs, rebuilt in the port's own code and confirmed in the machine code, with credit; its bundled decompilation stays unread, and its code, art and samples wait for its author's explicit yes | Accepted, amended by [0034](0034-retold-and-rechronicled-collaborate.md) |
| [0033](0033-the-project-is-aidyn-chronicles-enhanced.md) | The project is Aidyn Chronicles Enhanced, renamed from Aidyn Renewed: the code is `AidynEnhanced.*`, the tool is `aidyn-enhanced`, the data folder is `AidynEnhanced`; ACE's icon is the apps', and the full logo is the boot splash's and the title screen's in place of the original's | Superseded by [0040](0040-the-project-is-aidyn-chronicles-retold.md) (its names, its logo and icon), `aidyn.base` renamed by [0037](0037-the-rom-plugin-base-plugins-and-mods.md) |
| [0034](0034-retold-and-rechronicled-collaborate.md) | Aidyn Chronicles Retold and Aidyn ReChronicled stay two projects under their own names and primary developers, which collaborate and share assets freely both ways; findings are still confirmed in the machine code, code follows its licence, the decompilation stays unread, and nothing derived from the ROM is committed | Accepted |
| [0035](0035-the-world-is-edited-through-gltf.md) | The world is edited through a glTF round trip, one chunk per file: the scenery, the collision with a material per surface and role, and the map objects as nodes, written back into a mod as the assets and the patch that changed, with the collision flags and the object grid worked out again | Accepted |
| [0036](0036-the-mouse-turns-the-camera-by-dragging.md) | The mouse turns the camera as World of Warcraft's does: the cursor is free, a drag with either button held turns the camera, a press without a drag is a click, and both buttons run him forward | Accepted |
| [0037](0037-the-rom-plugin-base-plugins-and-mods.md) | The import is the ROM plugin, `aidyn.rom`; a base plugin is one the owner makes and ships with the remake, and a mod is one someone else makes; "the original game" replaces "the base game" | Accepted |
| [0038](0038-only-the-unmodified-1.0-rom-imports.md) | Only the unmodified NA 1.0 ROM imports, so the ROM plugin is the same for every player; a data edit is still told as one, for the refusal and the CLI's dumps, and its changes are made as base plugins | Accepted |
| [0039](0039-base-plugins-ship-beside-the-apps.md) | Base plugins ship in the release, in `plugins` beside the apps (a macOS bundle's `Contents/Resources`), or where `ACRE_BASE_PLUGINS` says in development, and load between the ROM plugin and the mods; packaging takes them from the owner's private repository with a `NOTICE.md` for their art and music | Accepted, added to by [0041](0041-the-art-and-music-are-the-private-repositorys.md) |
| [0040](0040-the-project-is-aidyn-chronicles-retold.md) | The project is Aidyn Chronicles Retold, renamed from Aidyn Chronicles Enhanced as it retells the story: the code is `AidynRetold.*` and the data folder `AidynRetold`; ACRE is the short name (`acre`, `acre-editor`, `ACRE_*`) and the base, the base plugins' IDs starting `acre` and the game's own content in `acre:` | Accepted |
| [0041](0041-the-art-and-music-are-the-private-repositorys.md) | Only art and music go in the private repository, `Aidyn Retold Private`, beside this one: the game's own art and the title's logo are the `acre` base plugin's images, read by key from the plugin set, the owner's other plugins are `acre_*` base plugins there, and the branding is kept there, its icons gitignored copies here | Accepted |

Statuses: **Proposed** means drafted and waiting for review. **Accepted** means agreed. **Superseded** means replaced by a later record, which it links to.
