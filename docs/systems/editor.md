# The editor (roadmap 0.6)

Per [ADR 0009](../adr/0009-code-organisation.md), the editor (first called the Inspector, [ADR 0028](../adr/0028-the-project-is-hbht.md)) is the one tool app. Per [ADR 0010](../adr/0010-editor-reads-plugins.md), it's the editor, which reads only the imported plugins and draws them with the runtime's code. New research into formats uses the CLI's dumps and exports.

`src/AidynRetold.Editor` is a Godot app. Run it with `tools/godot.ps1 --path src/AidynRetold.Editor` (build it first with `dotnet build`, or open it in the editor). It draws with the views it shares with the runtime in `AidynRetold.Views` (ADR 0022), and the runtime uses nothing of the editor's.

## The import dialog

The ROM is asked for in one place, at startup, when the ROM plugin is missing or out of date (`RomPlugin.Diagnose`) ([ADR 0043](../adr/0043-the-rom-is-asked-for-once-and-fixes-are-base-plugins.md)). The editor shows the import dialog (`ImportDialog`, a window over the empty editor, which takes the input from everything else) before the record browser loads anything, and the game, finding the same, starts the editor with `--from-game 1` and quits ([runtime](runtime.md#with-no-import)). It's the player's first run (ADR 0012), so it's plain and in the user's words: "The Aidyn Chronicles Retold Editor requires a North American 1.0 ROM.", or, started by the game, "Aidyn Chronicles Retold requires a North American 1.0 ROM." with the window titled for the game; the ROM's path with **Browse...**; and **Import** and **Cancel**. An import that's out of date rather than missing adds a line above saying it's from an older version of Aidyn Chronicles Retold and has to be done again. There's nothing to choose: the import corrects nothing, and the mushroom's fix is the ACRE plugin's ([hardcoded content](../hardcoded-content.md#corrections-to-the-roms-maps)).

- **The ROM.** Browse filters to `*.z64`, `*.n64` and `*.v64`; `RomImage` reads any of the three byte orders whatever the extension. `ImportableRom.Open` (in `AidynRetold.Rom`) takes the unmodified NA 1.0 alone, though the CLI also imports 1.1, and words what's wrong for the player: no file, not an N64 ROM, an N64 ROM Aidyn Chronicles Retold doesn't know (with its SHA-1 and 1.0's), a ROM hack of 1.0 ([ADR 0038](../adr/0038-only-the-unmodified-1.0-rom-imports.md)), or another version by name. What's wrong shows in the dialog and the player can pick another.
- **Importing** runs `RomImporter.Import` off the main thread into the plugins folder's `aidyn.rom`, showing its steps; the controls are disabled meanwhile, the dialog won't close, and an error shows in it. Then it remembers the ROM's path in `rom.txt` beside the plugins folder (`DataPaths.LastRomFor`: the data folder, for its own), which the dialog fills in next time.
- **Cancel,** or closing the dialog, quits the editor, so neither it nor the game goes on without an import.
- **After.** Started by the game, it says the import is done and shows **Play**, which starts the game (`AppLauncher.LaunchGame`) and closes the editor, or says to start it if it can't. Otherwise the dialog closes and the editor goes on into the record browser with the new plugins.

There's no import later: the browser has no **Import ROM…**, and no **Plugins folder…** to pick another folder by, the user's choice (Nov 3, 2026); `--data` loads another for a scripted run.

## The editor's game

The editor holds one game, the core's `GameState` ([saves](saves.md)), which flag pages show and set, scripts play against and change, and the party's pages show or try things on. Its sky, over the chunk it stands in at its time of day (`EditorGame.Sky`), lights the previews' lit meshes as trek's sky lights the runtime's ([rendering](rendering.md#the-n64-material)). A flag page's buttons change it:

- **Load Checkpoint** reads an ares state (see the [reference rig](../reference-rig.md)) as a save made from it loads (`CheckpointSave`), and says whether the core's network reproduces the console's derived flags, marking any the console has otherwise (such as the new journal entry flag, which loading clears). A state without a party gives a new game's party with the checkpoint's flags.
- **Load Save** loads a save from the data folder's `saves` and lists anything it couldn't use.
- **Save Game** saves the game as the editor has it, where the save or checkpoint it came from stood, so the runtime can start from it (`--save`).
- **New game** goes back to a new game's.

## Plugins

It loads the plugins folder as the runtime does (`PluginSet.LoadInstalled`: `aidyn.rom`, then the ACRE plugin wherever `DataPaths.AcrePlugin` says ([runtime](runtime.md#the-acre-plugin)), then the mods, ordered by their dependencies and load-after hints, by ID where those leave it open), from the data folder ([runtime](runtime.md#the-data-folder)) or wherever `--data` points. At startup a missing or out-of-date import opens the import dialog. A ROM plugin gone or replaced while it runs, found when the map view's save loads the plugins again, shows `RomPlugin.Diagnose`'s words instead of loading.

- **The layout.** A toolbar along the top (nine picture buttons at its left, then back and forward, each in a box of its own; what's gone wrong, if anything; **Saving to:**; **Light mode**). The picture buttons each list a type and open a page: **Map** lists the map chunks and opens the Overworld's map view; **Party**, **Characters** and **Enemies** list that kind of entity, below, and open Alaron, a commoner and a goblin; **Items** lists the items and opens the inventory rules, the Party tab's; **Shop**, **Weapons**, **Armor** and **Shield** list those and open the first. Their pictures are the ACRE plugin's own art (`acre:image/editor_map` and the rest, ADR 0041); without it they're words., a side panel with the type and the search over the list and the list's count under it, and the record's page beside it, one panel (`PagePanel`) that meets the toolbar's line with no gap, padded at its own top. Back and forward are also Alt+Left and Alt+Right, or the mouse's side buttons, which do nothing while a dialog is open (`EditorDialog.IsOpen`). What's gone wrong is the page's own, cleared as another page opens. While the plugins load, which takes a few seconds, the page shows a card saying so, with a bar that moves (`LoadingPage`); if they can't be loaded, as with a mod's bad manifest, a patch of a record no plugin has or a loop in the dependencies, the page says why, with **Load Again**.
- **The start page** (`StartPage`), before a record is picked: what's loaded, cards for the places most edits start (the overworld, Alaron, the Party tab, the world map, combat's and magic's rules, a new game, the title screen), every type by its IDs' spelling under a heading (`TypeGroups`: World, Characters, Items, Magic and combat, Story, Models and art, Sound) with its count, each a link that lists it, the plugins in load order with what each is ("The original game" for the ROM plugin, "The remade game" for the ACRE plugin, "User-generated mod" for a mod, and which is the one saving to), and the keys that find things. The validation report leads it when a record can't be read.
- **The list** is every record and every asset, by type (`PluginCatalog` in `AidynRetold.Plugins`). Scenes, textures and UI images are assets with no record, so they're listed by their asset's ID. The ROM plugin's IDs are shown without `aidyn:`, which they all share (the whole ID is the tooltip), and a mod's with its namespace. The Borg column is the archive index an original-game ID's hex key stands for. Every type has a summary: a name where it has one, and what it holds where it hasn't, naming the records it names by their names (a shop is its shopkeeper's, a recipe what it makes, a trigger its event and effects, a one-of-a-kind record such as `aidyn:combat/0` what it covers), and a flag with no label what names it. The search (Ctrl+F; Escape clears it) filters by ID, Borg index or summary (`I08` finds the chunk's map), and from three letters finds scripts by what they say, showing the first line that matches. An actor's summary leads with the characters whose body it is, entities and then dialogue entities, and a model's with the actors it's the scene or head of, under those names, or the items whose model it is (`PluginCatalog.Whose`), so `Brenna` finds her entity, her actor and her model. While entities are listed, three buttons under the search, **Party**, **Characters** and **Enemies**, each list one kind of them (`EntityRecord.Kind`, [characters](characters.md#the-records)): the party, the story characters, NPCs, trainers and shopkeepers, and the monsters and enemies; the one pressed, pressed again, lists them all. An entity of none of those kinds, which no entity of the original game is, is listed only with them all.
- **Links.** Any field whose value parses as a record ID is a link, so new record types need no editor code. A link to a record no plugin has, such as a flag, opens a page showing what names it.
- **Preview** (`RecordBrowser` picks the panel). Each kind of record previews with the runtime's or the core's own code, against the editor's game where rules come in:
  - **A scene** in the model view (`ModelView`) with the N64 material: its animations, looped and scrubbed by the tick (a clip whose keys all hold one pose, such as a still actor's resting one, starts paused, `ModelView.Moves`), with **Wireframe**, **Model's camera** (the model's own camera at 4:3) and **Emitters** (each particle emitter marked on its locator). A clip's length is one loop, as the runtime counts it.
  - **An actor** (`ActorPanel`): its scene in its initial state, without Alaron's head, and its states and branches. **Root in place** zeroes the root's position as the game draws it, and **Drive** runs the state machine for a request with `ActorAnimator` and `ActorMotion`, moving it by its root motion and starting its emitters as it enters states ([particles](../formats/particles.md)): `--record aidyn:actor/0x2BD7 --drive 5` shows Oriana's orb. While it's driven the clip list and Root in place are greyed, as the states pick the clips and driving always holds the root, and a still actor, with no clips, shows its states' ticks and Pause. Clicking a state marks that state while its clip plays, not the first state that plays the same clip.
  - **A flag** or **journal entry** (`FlagPanel`): its value in the editor's game, its label, a derived flag's formula with each input's value (the first input is the lowest bit), and a check box to set a plain flag.
  - **A script** (`ScriptPanel`): its nodes as a graph of cards, a card being a run of lines that each lead only to the next. **Play** runs it with the core's `ScriptRunner` against the editor's game (`GameState.RunScript`, so it draws from the game's random streams as the runtime's do), drawing the conversation box ([ui](ui.md)) under the graph, as wide as it and cut to the box, from its feathering's top to the screen's foot, with none of the screen above it (`DialoguePreview`): the mouse works it as the game's does (`DialogueBox.PointAt`), over a choice pointing at it, and a click is A, taking the choice pointed at or moving the script on; once it's clicked, Up and Down move between the choices and Enter or Space is A, as a controller would. While no box shows it says why: Play starts it, the script waits on the button beside, or it's ended. The page isn't said again beside it, and the graph marks its node; plugins with no fonts to draw it in get the page beside, its choices and A as buttons. The panel beside the graph has **Play** and **Skip** (only while it runs), how the box is drawn (its filter, the window's shape and its lines, but no zoom, as it fills the graph's width, each choice showing what the screen draws to begin with), what the script asks about and what it did. What the script asks about (members, items, gold, any skill check fixed at a step) can be changed in place; what it does changes the editor's game, and its cues and transitions are logged.
  - **An entity** is a page that edits it ([below](#an-entitys-page)).
  - **A weapon, armor or item** is a page that edits it ([below](#an-items-page)). **A shop, a loot table or a recipe** (`ItemPanels`): tried on a copy of the editor's party (`GameState.CopyParty`), so trying things leaves the game alone. A shop opens its window on the editor's game ([ui](ui.md#the-shop)), so the barterer pays its Stamina; a loot table rolls once into the loot window ([ui](ui.md#the-loot-window)), or 10,000 times for its averages.
  - **The inventory record** (`aidyn:inventory/0`, `PartyTabPanel`): the editor's game's party in the Party tab, drawn by `PartyTabView` ([ui](ui.md#the-pause-menu)), with buttons for the controller's. It, `BarterWindowPanel` and `TrainingWindowPanel` are `MenuWindowPanel`s, which hold the UI screen and its options, the button bar, the Details checkbox and `--press`'s names for the window they preview (an `IPartyWindow`).
  - **A map set or a map** (`MapSetView`): drawn whole with the runtime's `ChunkScenery` (ADR 0010), each object at its nearest level of detail; a map is its 3×3 framed on its own, and **Whole map set** loads the rest. Switches for terrain, scenery, collision coloured by surface or role (`CollisionLayer`), the chunk grid, the map objects by type (`MapObjects`; their names are Plugins' `MapObjectKinds`), the Expansion Pak, and **Flags**, which leaves out what isn't there by the editor's game's flags (the core's `MapObjectPresence`). The camera is `Orbit`.
  - **A map object** (`aidyn:voxel/<map>/<index>`): its map's chunks with it picked, its radius and a line to each object it names. A container can be opened in the loot window, rolling what it holds without setting its flags, and a camera object looked through, from where the player triggers it.
  - **Textures, UI images** and the images other records name (`ImageGallery`), blown up; click one to open it. A page's portraits and icons are drawn at the size the game draws them (`PagePanel.Picture`, by `PluginSet.ImageSize`), a larger replacement, such as the redrawn art's, smoothed into that size as the game does, not drawn larger.
  - **Anything else** shows its fields, as the Fields tab does.
- **Fields:** the merged record as its JSON, with the plugins that set each top-level field, in load order (`PluginSet.Setters`), and each link followed by what it names, such as a character's name; a map object's fields are its map's `objects[<index>].<field>`, so a mod that patched one object shows on that object alone. Lists come in pages of 256. The header says which plugin defines the record, which patch it (`PluginSet.Patchers`), and which plugin each asset file comes from. The start page counts the fields more than one plugin patched ([importer](importer.md), the conflict report).
- **Used by:** every record that names this one, with the fields that do. Terrains show nothing here, since chunks name them by number rather than record ID.
- **Atlas** (`AtlasView`, over `QuestIndex` in `AidynRetold.Plugins`), only on the types the index reads (`QuestIndex.CoveredTypes`: flags, scripts, journal entries, maps and their objects, map sets, shops, entities, items and the state flags), so an actor, a scene or a weapon has no Atlas tab: for a flag, what sets, clears and reads it, from scripts, derived flags, journal entries, the engine, map objects and chunks' world map regions; for a script, what it reads and sets and what starts it. Below, the graph around it, upstream, downstream or both, up to 160 records (`AtlasView.NodeLimit`), hiding the flags the engine writes its state into unless asked. Key items and members count as their flags: giving a key item sets its held and region flags, and AddMember sets a member's joined flag. The CLI's `acre flag` reads the same index. Boss flags, which winning a battle sets (`CombatRecord.Bosses`), and trigger records aren't in the index yet.

## The look

The editor has a theme of its own, dark by default or light (`EditorTheme`): the toolbar's **Light mode** switches between them, and the choice is kept in `user://editor.cfg` (`--light 1` or `0` picks one for a run without keeping it). Both are one look in two palettes, on the owner's scale for the UI they design: 13 for text and controls, 12 for help, 11 in capitals for a table's heads and a band's label, 16 for a card's title, 18 for a heading and 22 for a page's title; a crisp 1px border round every panel, a list, the 3D view's frame, a card, and a lighter rule between a table's or a card's rows; a radius of 4 on a control and 8 on a card; a card's head 16 by 24 in over a line, its body and rows 18 by 24, a control 6 by 10 or 12, 16 between cards, every box padded alike top and bottom; outlined buttons with a filled primary, its own drawn check boxes, switches and arrows, chips as pills, and the tab picked underlined 2. A card is `Card` with `CardHead` and `CardBody` or `CardRow`s, which `Section` makes and folds. A table in a card fills it to the card's border, which stays round it, unpadded, with no column heads, its folds' arrows 12 in from the edge as its text is (`Section`'s flush, `FlushTree`). A short table, in a card or in a box of its own (`ListBox`), is exactly as high as the rows it shows, growing as a branch opens, and its last row ends on the card's or the box's border, with no rule or space under it (`FittedTable`: a tree draws each row's rule on the row's last pixel and lays itself out 12 taller than its rows, so it's cut a pixel short of its last row, masked by its own rounded foot); past nine rows, or twelve for an armor's fields, it scrolls. A card's buttons stand two to a row, each exactly half of it (three, a third each, under a shield's model), or one alone, centred (`ButtonRows`). Pages name what they show by the theme's type variations (`DimLabel`, `Chip`, `ChangedLabel`, `PrimaryButton` and the rest), so a change of mode reaches them, and the browser shows the page again for what's drawn by code (a tree's colours, the timeline, the 3D views' backgrounds, `EditorTheme.Viewport`).

Every dialog is the editor's own (`EditorDialog`), in the owner's style: a box of a fixed width over a dimmed backdrop, its title over a line, 16 by 24 in, its message in paragraphs, and its buttons at its foot's right, Cancel first and the way forward last, filled, red where it takes something away; focus starts on Cancel, and the cross at the title's right, Escape and the backdrop cancel, but for the import dialog and the first asking for a mod, which the editor can't go on without. What's saved, the editor calls saving to a mod. Chips name the plugins (`EditorStyle.PluginName`): the ROM plugin AC ROM, the ACRE plugin AC Retold, and a mod by its ID, each word capitalized and underscores as spaces (`texture_test` is Texture Test).

## The mod saved to

The editor saves to one mod at a time (`CurrentMod`), remembered for each plugins folder in `user://editor.cfg`. When it opens with none remembered, or the one remembered is gone, it asks before anything loads, after the import if there's one to do, in the import dialog's place and size, and as it does, with nothing else to use (`ModSetup`): **Load Existing Mod** picks a mod's `plugin.json`, which must be in the plugins folder (or be the ACRE plugin's), so it loads with the rest; **Create New Mod** asks its name, makes its ID from it (`My Village` is `my_village`) and its folder; and **Just looking around** goes on with none, so the first save opens the same dialog, and the mod it loads or makes is then the one (`PluginFiles.ModAsync`). The toolbar's **Saving to:** shows the mod and changes it, in the same dialog, which its cross closes, keeping the mod there was.

A save goes to the mod without asking and shows a toast for three seconds (`Toast`): what was saved to which mod, named as its chip names it (`EditorStyle.ModName`: the Texture Test mod, or the ACRE plugin), with **Undo**. The save notes each file it overwrites or removes as it was first (`ModFolder.Journal`), and Undo puts them back (`ModFolder.Restore`) and loads the plugins again. A save that goes wrong partway puts back what it had written, so nothing's left half saved. Taking something out of a mod asks first, being a deletion, then toasts the same.

Loading the plugins again, after a save, its Undo or a texture or model replaced, keeps the page, the history, the type listed and the game shown (a checkpoint's or a save's, as played and set, `EditorGame.Carry`); an armor's, a weapon's or an item's page keeps the changes it holds; a map's keeps its camera and the chunks loaded (`MapSetView.KeepView`). Leaving an edit page that holds changes asks first: **Keep Editing**, or **Discard Changes**.

## A record's page

The header is one row (`RecordHeader`): the record's summary, large (a one-of-a-kind record by its type's name, such as Combat rules, and a texture, UI image, animation or sample by its type and key), its ID and Borg dim, which a click copies, one chip for the last plugin that touches it: grey for a ROM plugin record as it is, green for a record a plugin added, and orange for one a plugin patches or whose file it replaces, whichever plugin defined it, the ACRE plugin's or another's (the whole chain, with the fields each patcher sets, is the chip's tooltip), and the page's tabs at its end, which the `TabContainer` under it doesn't draw. An actor's, a model's, an armor's, a weapon's and an item's page is one page, with what the tabs would hold in its cards, so it has none.

## A model's page

An actor's or a scene's preview is the model view (`ModelView`), in two columns. The left: the view, framed, with its note over its corner; under it, one bar of play, the clip and the tick, the actor's Drive controls (`ActorPanel.Bar`) and the view's switches; then one row of the states' **Table** and **Graph** and the timeline (`Timeline`), as high as the buttons, which scrubs by the tick and marks what happens when in the clip; then the actor's states, which take the rest of the height the split under the view gives. The header stands over the left column alone, so the right runs the page's full height, just wide enough to begin with for four textures across, the card's padding as wide at their right as at their left (`ModelInspector.Width`, from `TexturesSection.FourAcrossCard`), and as wide as it's dragged: the inspector (`ModelInspector`), cards that fold and stay as they were left (`Section`): the record's **Used by** first, then the model's cards, then the record's **Fields**, in place of the tabs, and for an actor **Body** and then **Parts** last of all, which takes the height that's left and lists what's held and the head as they hang from the locators, not the view's own marks (a model's parts follow its textures). The inspector goes with the model when another page opens. Body's **Scale** frames the view again at the model's new size. An actor's inspector starts with **Shown as**: the entities and dialogue entities whose body the actor is, whose body, held items and strike the sections show.

- **Model** (`ModelSection`): what the file holds, with the plugin it comes from in the card's note (the model's ID is the view's note and the header's), and under it, set apart, **Export Model**, **Replace Model** and **Put Back Original**. A replaced model's note is the plugin replacing it and how its check came out. Replacing runs the remodel check of the picked file against the original first (`RemodelCheck`, in Plugins) and shows it before anything's written. **Put Back Original** takes the top mod's model out, so what it replaced shows again: the original, or another mod's. A replaced model shows a **Replacement / Original** switch, which shows the original's file, with its own textures, not the plugins' PNGs, and the actor as the ROM plugin has it (the ROM plugin loaded alone, once, `RecordBrowser.OriginalPluginsAsync`), and the check of the replacement: the root part, every animation with its length, the locators and their attachments, the lights and camera, the model's extras, new names the game reads as parts, and whether its textures keep their numbers.
- **Textures** (`TexturesSection`): a tile for each image the model has, drawn as the game draws it, a plugin's PNG in place of the model's copy where there's one ([ADR 0044](../adr/0044-textures-on-models-come-from-a-plugins-pngs.md)), in orange; a remodel's own images have no number. The one picked says where it comes from where that's a plugin's PNG or the model's own image (a texture is the copy in the model's file unless said), and how many other models use it, listed in a box of their own under that, a row each, who wears the model as a link with its key, or the model by its key, double-clicked to open (`TextureUsage`, built off the main thread when first asked, once per load), with **Export Texture**, which asks whether to export this texture or all the model's, **Replace Texture**, which asks whether on this model alone (a model texture) or on every model that uses it (the texture's own PNG), and **Put Back Texture** where a plugin's PNG is in its place.
- **Parts** (`PartsSection`): the model's tree of nodes, each with what the game reads it as by its name (`SceneNames`): a part, the actor's root part, a locator and what the game hangs there (0 a weapon or a bow's arrow, 1 a bow, 2 a shield, 3 Alaron's head or a Troubadour's notes), an attachment, a light, an emitter, the camera, a billboard, or a remodel's skeleton and meshes. The one picked is marked in the view as it moves: a box round its own meshes, or its axes for a node with none.
- **Outfits and held** (`HeldSection`): an actor's outfits, each with what it's worn over, starting on the one the character shown would wear by its gear, and picking one shows its meshes and hides the others' (the game's `OutfitSwitch` taken off); a weapon and a shield to try, the character's own to start with, hung where the game hangs them as it fights (`Combatant.Holding`, `Attachments.Find`, which the runtime's bodies use too), with no shield for one who can never learn the skill; and the actor's separate head, Alaron's, on its locator.
- **Body** (`BodySection`): the character's radius, height, scale and strike, drawn on the model when ticked: the collision sphere with its footprint and a ring at its height (both off to begin with), Alaron's figure beside it for size, and the model at the game's scale.

The states show as a table or as a graph (`ActorPanel.Graph.cs`, a `GraphEdit`): a card per state, its animation and length in its title and a row per branch joined to the state it leads to, orange where it interrupts, the cards in columns by how many branches from the initial state reach them and the states it never reaches in the last. Picking a card picks its state, as a row of the table does.

The timeline's marks are the clip's as the game times them for the character shown (`TimelineMarks`), from the requests whose branches lead into the states that play it: a footstep key of the body's footstep set on its first surface, and a key of its own, at its share of the state's length (`AudioKeys.Reached`); an emitter of the scene's that starts on one of those requests, on the state's first tick and its delay after (`ActorParticles.Entered`); and for an attack, request 12 to 18, the tick the blow lands, at the character's strike share, or 0.4 for a bow shot or a throw (`Battle.AtStrike`). While the actor is driven, it shows the state playing, and its clock.

What the sections write is saved to the mod saved to ([below](#the-mod-saved-to)), or into the ACRE plugin's own folder for the ID `acre` (`PluginFiles.Write`, through `ModFolder.OpenOrCreate`). Then the browser loads the plugins again and opens the page again, so it shows what was written.

## An item's page

An armor's, a shield's, a weapon's or an item's page is one page of cards, with no tabs (`ItemEditPage`, which `ArmorPage`, `ShieldPage`, `WeaponPage` and `ItemPage` give their rows), and beside them, where it has one, its model: the scene the game draws for it (its `model`, a Borg5 scene, not an actor, so it has no states), in a card the page's height, the view 8 in from its edges, framed whole (`ModelThumb`, its field of view the narrower side's), turned by dragging and zoomed by scrolling, with **Export Model**, **Replace Model** (`ModelSection.FileButtons`, the model card's own) and **Open Model** for the model's own page in one row under it; and under that card the model's **Textures**, the model page's card (`TexturesSection`), which reads the model's file parsed by itself where there's no model view (`ModelContext.Glb`). The panel scrolls when its cards are taller than the page, and follows the values that decide it as they're changed, before they're saved. Where the model's drawn:

- **A shield's** the game hangs on a body's arm in battle (`Combatant.Holding`), and **a weapon's** it puts in the hand, a bow's arrow in the hand and the bow in the other; both have a **Model** row, the model by the other shields or weapons that share it, with **Change Model**, which picks one of the models the game's shields or weapons have, or none, the one picked turning beside the list. One with none shows a card saying the game draws nothing there, with **Choose Model**: a shield shows as no shield at all, and a bite, a claw and the other natural weapons have none, as the body's own model strikes. Body armor, its own type apart from the shields since Nov 5, 2026 (`aidyn:armor` and `aidyn:shield`, [items](items.md#the-records)), has no panel, as the game draws it as the body's outfit.
- **An item's** the game draws in no battle, so only the six items that have one (three wands, Kendall's Hat, Pandara's Amulet and the Letter to Txomin) show it, to look at and edit its textures, with no Model row.

The cards:

- **The card**, titled with what it is (Shield, Weapon, Ring, Scroll, Key item), a row for each value, its label in a column of its own and a line under its control saying what it is: its picture, in a well, with **Change Picture**, which picks from every picture the game's weapons, armor and items have, nine across, the grid as wide as the dialog's words so its edges stand as far from the first column as from the last, or a PNG of one's own; its name; then its own values; and what it gives beyond them (its aspect, a stat or skill, a spell, a resistance), which **All fields** lists.
  - **Armor:** its price, protection, Dexterity, Stealth and experience bonus. **A shield:** its model, then the same with its defense.
  - **A weapon:** its class, which is the skill wielding it needs, its model, its price, damage, hit, range, its damage's element, the Strength it needs, its attack animation, whether it can be taken off once equipped, and its experience modifier.
  - **An item:** its kind, which changes only among the worn kinds (a potion's effects, a scroll's spell and a key's flags go with theirs, so theirs is shown, not changed); its price; a potion's, a scroll's or another item's description, which the game's details show, over several lines (an amulet's, kept in the game's text, is shown as one the game doesn't show); worn gear's damage, protection and the Strength and Intelligence it needs; and its experience multiplier. A potion's effects and a key item's flags are only in **All fields**.

  Changes are held, counted in the card's head, until **Save** writes them to the mod as one change, with the toast and its Undo, or **Discard** puts them back. Saving merges them into the mod's own record of it where it defines it, or else its patch of the record that loads last, wherever it is, so the save isn't lost to another patch of it, or else a new patch in its records file (`records/armor.json`, `shields.json`, `weapons.json`, `items.json`; `ModFolder.Record`, `ModFolder.FileDefining`, `ModFolder.FilePatching`), and a picture from a file is written as the mod's own image, `<mod>:image/armor_<key>` (`weapon_`, `item_`), which its icon then names. As the game lays a picture out at its own size and the mod's own image has no original to be drawn into, a PNG from a file is fitted to the original picture's size as it's picked, its shape kept. A number counts as it's typed, so **Save** is there without Enter first, and the card's title follows a change of what it is (Armor to Shield).
- **In the game**: its details exactly as the game shows them when C-down is held on it, built by the menus' own `MenuDetailsBuilder.Item` from the ROM's own words (`MenuText`): its icon and name, then a weapon's skill, aspect, Min. Strength, Base Hit and Damage; armor's aspect, Protection, a shield's Defense, Dexterity and Stealth, and Total Protection and Total Defense now and with it on, the second green or red, for the editor's first party member, whom the card's note names; worn gear's Min. Intelligence and Strength, Damage and Protection; and what it adds. A potion, a scroll or another item shows its description, and a scroll its spell's Min. Wizard Rank; a key item and an item with no description show nothing ([ui](ui.md#the-party-tab)'s C-down details). Armor and weapons have no description in the game.
- **Used by**: what names it, double-clicked to open (`UsedByList`).
- **All fields**, folded: the record as the plugins merge it.

## An entity's page

An entity's page is an edit page like an item's (`EntityPage`, on `EditPage`, which `ItemEditPage` shares): one page of cards, no tabs, with **Save** and **Discard** on the card's head and the same held changes, saved as a patch in the mod's `entities.json`. Beside the cards, its body's model (its actor's scene, as the game draws it standing) with the model's textures under it, as a shield's page has; an entity whose body no plugin draws says so.

- **The card**: its portrait, with **Change Picture** picking from every portrait the game's characters have or a PNG; its name; **As it starts**, the sheet the game builds from the record with the changes held (hit points, experience); its kind (the entity DB's group), aspect, school, True Name and heavy; its level; then each **attribute** and **skill** as a button, which asks for a new value within the rules' caps (`StatRecord.BaseCap`, `SkillRecord.BaseCap`), a skill it can never learn greyed, which a click asks to allow (the skill then starts at 0; a skill's dialog can also make it one it can never learn); its spells, as links; its **equipment** as slots, two across; and its morale, experience, loot table, perception, protection, damage and resistances.
- **The slots** are by kind. A party member has its weapon, armor and shield, one slot for each kind of gear (helmet, cloak, gloves, ring, wand, belt, boots, amulet, scroll: the record's `gear`, the port's own, which `Character.Create` puts on by the rules), and the two weapons it brings into the inventory as it joins. An enemy or a character has its weapon, the weapon it draws first in battle (the record's third), its armor and its shield. A slot's dialog lists what the sheet may hold there, by its skills and stats as the record and the held changes have them (`Equipment.CanWield`, `CanCarryShield`, `CanWear`), each with what it does, and none; the rest are hidden and counted.
- **After the card**: for one who teaches, the game's training window against the editor's game ([ui](ui.md#training)); the atlas, only where the quest index has something on it; what names it; and all its fields.

## Traps

- **Many objects at once.** Every mesh the N64 material draws has instance uniforms, so the project raises Godot's global shader variable buffer (`rendering/limits/global_shader_variables/buffer_size`) for a whole map set's worth.
- **Freeing what's out of the tree.** Godot frees only what's in the tree when it quits, and reports everything else leaked, one by one, slow enough after a map set to look like a hang. The browser swaps the model view and the map view in and out of the preview rather than rebuilding them, and `Models` keeps each scene's parsed template out of the tree, so `RecordBrowser` frees the view not showing and disposes the models when it's deleted, as `Game` disposes its models. Anything else kept out of the tree needs the same.

## Editing the world

The map view edits map objects ([editing the world](../editing-the-world.md#in-the-editor), ADR 0035): a picked object (its marker, or a placed model by its meshes' bounds, `PlacedAt`), shown by its marker, a yellow box round its model (`SelectionBox`), its radius as a sphere, or as a flat ring for a scene object, whose radius is its draw distance, and the model itself in a small viewer in the panel (`ModelThumb`), is dragged along the collision keeping its height over it and where it was grabbed under the cursor, once the mouse has moved 4 pixels, or up and down with Shift, pressed or let go mid-drag going on from where it is, set by its position, rotation and scale spin boxes, dropped to the ground (the collision under it, cast from just over it, so not a bridge or a roof above), duplicated (Ctrl+D), deleted (Delete) or given new fields as JSON, read strictly as the game reads them, a scene object placed again as its models, tint or flags may have changed. The edits are a `WorldEdits` (Plugins' `World`), a working copy of each touched map's objects that the view shows in place of the record's and reapplies to the chunks' scenery (`ApplyEdits`, placing again or removing scene objects' nodes through `ChunkScenery.Place` and `Remove`); they outlive a reload of the plugins until saved or discarded, which asks first. **Save … to mod…** writes each map's patch with `MapPatch` against the plugins below the mod and `ModFolder`, and has the browser load the plugins again, so the view shows the mod's records. The view stays up as another of its objects is picked, keeping the keys' focus, and goes on loading chunks while another page shows. A moved model's billboards, whose facing nodes are top-level, are turned to the camera again at once (`Billboards.Face`), and its picking bounds are worked out again (`BoundsOf`). Terrain and collision are edited in Blender through the CLI's `chunk export` and `chunk import`, which write through the same `ModFolder`.

## The command line

`tools/godot.ps1 --path src/AidynRetold.Editor -- --record aidyn:mapset/0 --tab preview --screenshot out/shot.png` opens a record, saves the window and quits. It gives up after a minute, so a hang can't block a script. `Editor` parses the options and takes the screenshot with the views' `CommandLine`, as the runtime does.

- **The page:** `--record <id>`, `--tab preview|fields|used-by|atlas` (picked once the record shows, and left on Preview for a tab the record hasn't, such as an actor's atlas), `--data <plugins folder>`. `--type <type>` lists that type, as the side panel's dropdown does, `--kind party|character|enemy` that kind of entity, as its buttons do, and `--go map|party|characters|enemies|items|shop|weapons|armor|shield` presses that quick button on the toolbar. `--page-scroll <pixels>` scrolls an edit page's cards down that far, for a screenshot of what's below the fold.
- **The import dialog**, with no current import: `--from-game 1` (which the game passes) ends it with Play; `--rom <path>` and `--import 1` fill it in and press Import, and a screenshot waits for the import, giving up after 15 minutes rather than one. Without `--import`, `--screenshot` saves the dialog as it opens.
- **The game:** `--checkpoint <state>` or `--save <save>` loads that game; `--play <moves>` plays a script that many moves, taking first choices, with its conversation box.
- **The UI screen** (the conversation box and the windows): `--zoom <1-3>` (not on a script's page, whose box fills the graph's width), `--ui-filter pixels|videoout|smooth`, `--aspect 4:3|16:9`, `--ui-lines <n>`.
- **The mod and the look:** `--mod <id>` saves to that mod for the run, without asking; a screenshot run doesn't ask which mod, unless `--mod-dialog 1`, which saves the dialog, or `--mod-dialog toolbar`, which opens the toolbar's; `--loading 1` saves the loading card, while the plugins load; on an armor's, a weapon's or an item's page, `--item-change name=…,price=…` holds values as if typed, `--item-save 1` saves them, `--item-picture 1` opens the picture's dialog and `--item-model 1` the model's (the `--armor-` spellings do the same); `--toast <text>` shows a toast; `--light 1` or `0` picks the mode for the run.
- **A model's inspector:** `--open model,parts` opens those sections and folds the rest; `--part "transform 12"` picks a part; `--states graph` shows an actor's states as the graph.
- **Scenes and maps:** `--drive <request>` drives an actor; `--wireframe 1` and `--scene-camera 1` set those switches (the second is **Model's camera**); `--collision surface|role` colours a map's collision; `--look 1` looks through a camera object's camera.
- **The Party tab and windows:** `--member <slot>`, `--list inventory|spells|skills|stats`, `--row <n>`, `--details 1`; `--roll 1` rolls a loot table or opens a container's loot window; `--press a,b,up,down` presses a window's buttons in turn, with `left` and `right` in the loot window, `cup` in a shop's and `cleft` and `cright` in a training window.
- **Screenshots:** `--wait <seconds>` waits first; `--ui-screenshot <png>` saves the UI screen too, in its own pixels.
