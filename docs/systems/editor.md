# The editor (roadmap 0.6)

Per [ADR 0009](../adr/0009-code-organisation.md), the editor (first called the Inspector, [ADR 0028](../adr/0028-the-project-is-hbht.md)) is the one tool app. Per [ADR 0010](../adr/0010-editor-reads-plugins.md), it's the editor, which reads only the imported plugins and draws them with the runtime's code. New research into formats uses the CLI's dumps and exports.

`src/AidynRetold.Editor` is a Godot app. Run it with `tools/godot.ps1 --path src/AidynRetold.Editor` (build it first with `dotnet build`, or open it in the editor). It draws with the views it shares with the runtime in `AidynRetold.Views` (ADR 0022), and the runtime uses nothing of the editor's.

## The import dialog

The ROM is asked for in one place, at startup, when the ROM plugin is missing or out of date (`RomPlugin.Diagnose`) ([ADR 0043](../adr/0043-the-rom-is-asked-for-once-and-fixes-are-base-plugins.md)). The editor shows the import dialog (`ImportDialog`, a window over the empty editor, which takes the input from everything else) before the record browser loads anything, and the game, finding the same, starts the editor with `--from-game 1` and quits ([runtime](runtime.md#with-no-import)). It's the player's first run (ADR 0012), so it's plain and in the user's words: "The Aidyn Chronicles Retold Editor requires a North American 1.0 ROM.", or, started by the game, "Aidyn Chronicles Retold requires a North American 1.0 ROM." with the window titled for the game; the ROM's path with **Browse...**; and **Import** and **Cancel**. An import that's out of date rather than missing adds a line above saying it's from an older version of Aidyn Chronicles Retold and has to be done again. There's nothing to choose: the import corrects nothing, and the mushroom's fix is the `acre_fixes` base plugin's ([hardcoded content](../hardcoded-content.md#corrections-to-the-roms-maps)).

- **The ROM.** Browse filters to `*.z64`, `*.n64` and `*.v64`; `RomImage` reads any of the three byte orders whatever the extension. `ImportableRom.Open` (in `AidynRetold.Rom`) takes the unmodified NA 1.0 alone, though the CLI also imports 1.1, and words what's wrong for the player: no file, not an N64 ROM, an N64 ROM Aidyn Chronicles Retold doesn't know (with its SHA-1 and 1.0's), a ROM hack of 1.0 ([ADR 0038](../adr/0038-only-the-unmodified-1.0-rom-imports.md)), or another version by name. What's wrong shows in the dialog and the player can pick another.
- **Importing** runs `RomImporter.Import` off the main thread into the plugins folder's `aidyn.rom`, showing its steps; the controls are disabled meanwhile, the dialog won't close, and an error shows in it. Then it remembers the ROM's path in `rom.txt` beside the plugins folder (`DataPaths.LastRomFor`: the data folder, for its own), which the dialog fills in next time.
- **Cancel,** or closing the dialog, quits the editor, so neither it nor the game goes on without an import.
- **After.** Started by the game, it says the import is done and shows **Play**, which starts the game (`AppLauncher.LaunchGame`) and closes the editor, or says to start it if it can't. Otherwise the dialog closes and the editor goes on into the record browser with the new plugins.

There's no import later: the browser has no **Import ROM…**, and no **Plugins folder…** to pick another folder by, the user's choice (Nov 3, 2026); `--data` loads another for a scripted run.

## The editor's game

The editor holds one game, the core's `GameState` ([saves](saves.md)), which flag pages show and set, scripts play against and change, and the party's pages show or try things on. Its sky, over the chunk it stands in at its time of day (`EditorGame.Sky`), lights the previews' lit meshes as trek's sky lights the runtime's ([rendering](rendering.md#the-n64-material)). A flag page's buttons change it:

- **Load checkpoint…** reads an ares state (see the [reference rig](../reference-rig.md)) as a save made from it loads (`CheckpointSave`), and says whether the core's network reproduces the console's derived flags, marking any the console has otherwise (such as the new journal entry flag, which loading clears). A state without a party gives a new game's party with the checkpoint's flags.
- **Load save…** loads a save from the data folder's `saves` and lists anything it couldn't use.
- **Save game…** saves the game as the editor has it, where the save or checkpoint it came from stood, so the runtime can start from it (`--save`).
- **New game** goes back to a new game's.

## Plugins

It loads the plugins folder as the runtime does (`PluginSet.LoadInstalled`: `aidyn.rom`, then the base plugins wherever `DataPaths.BasePlugins` says ([runtime](runtime.md#the-base-plugins)), then the rest, each ordered by their dependencies and load-after hints, by ID where those leave it open), from the data folder ([runtime](runtime.md#the-data-folder)) or wherever `--data` points. At startup a missing or out-of-date import opens the import dialog. A ROM plugin gone or replaced while it runs, found when the map view's save loads the plugins again, shows `RomPlugin.Diagnose`'s words instead of loading.

- **The list** is every record and every asset, by type (`PluginCatalog` in `AidynRetold.Plugins`). Scenes, textures and UI images are assets with no record, so they're listed by their asset's ID. The Borg column is the archive index a base-game ID's hex key stands for. The search filters by ID, Borg index or summary (`I08` finds the chunk's map), and from three letters finds scripts by what they say, showing the first line that matches. An actor's summary leads with the characters whose body it is, entities and then dialogue entities, and a model's with the actors it's the scene or head of, under those names, or the items whose model it is (`PluginCatalog.Whose`), so `Brenna` finds her entity, her actor and her model.
- **Links.** Any field whose value parses as a record ID is a link, so new record types need no editor code. A link to a record no plugin has, such as a flag, opens a page showing what names it.
- **Preview** (`RecordBrowser` picks the panel). Each kind of record previews with the runtime's or the core's own code, against the editor's game where rules come in:
  - **A scene** in the model view (`ModelView`) with the N64 material: its animations, looped and scrubbed by the tick, with **Wireframe**, **Scene camera** (the scene's own camera at 4:3) and **Emitters** (each particle emitter marked on its locator). A clip's length is one loop, as the runtime counts it.
  - **An actor** (`ActorPanel`): its scene in its initial state, without Alaron's head, and its states and branches. **Root in place** zeroes the root's position as the game draws it, and **Drive** runs the state machine for a request with `ActorAnimator` and `ActorMotion`, moving it by its root motion and starting its emitters as it enters states ([particles](../formats/particles.md)): `--record aidyn:actor/0x2BD7 --drive 5` shows Oriana's orb.
  - **A flag** or **journal entry** (`FlagPanel`): its value in the editor's game, its label, a derived flag's formula with each input's value (the first input is the lowest bit), and a check box to set a plain flag.
  - **A script** (`ScriptPanel`): its nodes as a graph of cards, a card being a run of lines that each lead only to the next. **Play** runs it with the core's `ScriptRunner` against the editor's game (`GameState.RunScript`, so it draws from the game's random streams as the runtime's do), drawing the conversation box ([ui](ui.md)). What the script asks about (members, items, gold, any skill check fixed at a step) can be changed in place; what it does changes the editor's game, and its cues and transitions are logged.
  - **An entity** (`CharacterPanel`): its character sheet from the core's `Character`, with training quoted by the core's `Training`, experience to award, and equipment taken off or put on by the core's rules. A member of a loaded game's party can show that game's sheet. A trainer's page ends with the training window ([ui](ui.md#training)).
  - **A weapon, armor or item, a shop, a loot table or a recipe** (`ItemPanels`): tried on a copy of the editor's party (`GameState.CopyParty`), so trying things leaves the game alone. A shop opens its window on the editor's game ([ui](ui.md#the-shop)), so the barterer pays its Stamina; a loot table rolls once into the loot window ([ui](ui.md#the-loot-window)), or 10,000 times for its averages.
  - **The inventory record** (`aidyn:inventory/0`, `PartyTabPanel`): the editor's game's party in the Party tab, drawn by `PartyTabView` ([ui](ui.md#the-pause-menu)), with buttons for the controller's. It, `BarterWindowPanel` and `TrainingWindowPanel` are `MenuWindowPanel`s, which hold the UI screen and its options, the button bar, the Details checkbox and `--press`'s names for the window they preview (an `IPartyWindow`).
  - **A map set or a map** (`MapSetView`): drawn whole with the runtime's `ChunkScenery` (ADR 0010), each object at its nearest level of detail; a map is its 3×3 framed on its own, and **Whole map set** loads the rest. Switches for terrain, scenery, collision coloured by surface or role (`CollisionLayer`), the chunk grid, the map objects by type (`MapObjects`; their names are Plugins' `MapObjectKinds`), the Expansion Pak, and **Flags**, which leaves out what isn't there by the editor's game's flags (the core's `MapObjectPresence`). The camera is `Orbit`.
  - **A map object** (`aidyn:voxel/<map>/<index>`): its map's chunks with it picked, its radius and a line to each object it names. A container can be opened in the loot window, rolling what it holds without setting its flags, and a camera object looked through, from where the player triggers it.
  - **Textures, UI images** and the images other records name (`ImageGallery`), blown up; click one to open it.
- **Fields:** the merged record as its JSON, with the plugins that set each top-level field, in load order (`PluginSet.Setters`); a map object's fields are its map's `objects[<index>].<field>`, so a mod that patched one object shows on that object alone. Lists come in pages of 256. The header says which plugin defines the record, which patch it (`PluginSet.Patchers`), and which plugin each asset file comes from. The status line after loading counts the fields more than one plugin patched ([importer](importer.md), the conflict report).
- **Used by:** every record that names this one, with the fields that do. Terrains show nothing here, since chunks name them by number rather than record ID.
- **Atlas** (`AtlasView`, over `QuestIndex` in `AidynRetold.Plugins`): for a flag, what sets, clears and reads it, from scripts, derived flags, journal entries, the engine, map objects and chunks' world map regions; for a script, what it reads and sets and what starts it. Below, the graph around it, upstream, downstream or both, up to 160 records (`AtlasView.NodeLimit`), hiding the flags the engine writes its state into unless asked. Key items and members count as their flags: giving a key item sets its held and region flags, and AddMember sets a member's joined flag. The CLI's `acre flag` reads the same index. Boss flags, which winning a battle sets (`CombatRecord.Bosses`), and trigger records aren't in the index yet.

## A record's page

The header is one row (`RecordHeader`): the record's summary, large, its ID and Borg dim, a chip for each plugin it comes from in load order (the definer, each patcher, with the fields it sets in its tooltip, and a plugin whose file replaces an earlier one's, in orange), and the page's tabs at its end, which the `TabContainer` under it doesn't draw.

## A model's page

An actor's or a scene's preview is the model view (`ModelView`): one toolbar (play, the clip, scrubbing by the tick, the actor's Drive controls, `ActorPanel.Bar`, and the view's switches), the view with its note over its corner, the actor's states under it, and an inspector beside them (`ModelInspector`), sections that fold and stay as they were left (`Section`). An actor's inspector starts with **Shown as**: the entities and dialogue entities whose body the actor is, whose body, held items and strike the sections show.

- **Model** (`ModelSection`): the model's ID and the plugins its file comes from, what the file holds, and **Export model…**, **Replace model…** and **Put back the original**. Replacing runs the remodel check of the picked file against the original first (`RemodelCheck`, in Plugins) and shows it before anything's written. A replaced model shows a **Replacement / Original** switch, which shows the original's file and the actor as the ROM plugin has it (the ROM plugin loaded alone, once, `RecordBrowser.OriginalPluginsAsync`), and the check of the replacement: the root part, every animation with its length, the locators and their attachments, the lights and camera, the model's extras, new names the game reads as parts, and whether its textures keep their numbers.
- **Textures** (`TexturesSection`): a tile for each image the model has, drawn as the game draws it, a plugin's PNG in place of the model's copy where there's one ([ADR 0044](../adr/0044-textures-on-models-come-from-a-plugins-pngs.md)), in orange; a remodel's own images have no number. The one picked says where it comes from and which other models use it, as links (`TextureUsage`, built off the main thread when first asked, once per load), with **Export PNG…**, **Export all…**, **Replace on this model…** (a model texture), **Replace everywhere…** (the texture's own PNG) and **Put back**.
- **Body** (`BodySection`): the character's radius, height, scale and strike, drawn on the model: the collision sphere with its footprint, a ring at its height, Alaron's figure beside it for size, and the model at the game's scale.

What the sections write goes into a plugin the person names, a mod or a base plugin in its own folder, remembered for the next write (`PluginFiles.Write`, through `ModFolder.OpenOrCreate`). Then the browser loads the plugins again and opens the page again, so it shows what was written.

## Traps

- **Many objects at once.** Every mesh the N64 material draws has instance uniforms, so the project raises Godot's global shader variable buffer (`rendering/limits/global_shader_variables/buffer_size`) for a whole map set's worth.
- **Freeing what's out of the tree.** Godot frees only what's in the tree when it quits, and reports everything else leaked, one by one, slow enough after a map set to look like a hang. The browser swaps the model view and the map view in and out of the preview rather than rebuilding them, and `Models` keeps each scene's parsed template out of the tree, so `RecordBrowser` frees the view not showing and disposes the models when it's deleted, as `Game` disposes its models. Anything else kept out of the tree needs the same.

## Editing the world

The map view edits map objects ([editing the world](../editing-the-world.md#in-the-editor), ADR 0035): a picked object (its marker, or a placed model by its meshes' bounds, `PlacedAt`), shown by its marker, a yellow box round its model (`SelectionBox`), its radius as a sphere, or as a flat ring for a scene object, whose radius is its draw distance, and the model itself in a small viewer in the panel (`ModelThumb`), is dragged along the collision keeping its height over it, or up and down with Shift, set by its position, rotation and scale spin boxes, dropped to the ground, duplicated (Ctrl+D), deleted (Delete) or given new fields as JSON, read strictly as the game reads them. The edits are a `WorldEdits` (Plugins' `World`), a working copy of each touched map's objects that the view shows in place of the record's and reapplies to the chunks' scenery (`ApplyEdits`, moving, placing or removing scene objects' nodes through `ChunkScenery.Place` and `Remove`); they outlive a reload of the plugins until saved or discarded. **Save … to mod…** asks a mod ID, writes each map's patch with `MapPatch` against the plugins below the mod and `ModFolder`, and has the browser load the plugins again, so the view shows the mod's records. The record header over the preview is hidden while the map view is up, as the panel says what's picked; a moved model's billboards, whose facing nodes are top-level, are turned to the camera again at once (`Billboards.Face`), and its picking bounds are worked out again (`BoundsOf`). Terrain and collision are edited in Blender through the CLI's `chunk export` and `chunk import`, which write through the same `ModFolder`.

## The command line

`tools/godot.ps1 --path src/AidynRetold.Editor -- --record aidyn:mapset/0 --tab preview --screenshot out/shot.png` opens a record, saves the window and quits. It gives up after a minute, so a hang can't block a script. `Editor` parses the options and takes the screenshot with the views' `CommandLine`, as the runtime does.

- **The page:** `--record <id>`, `--tab preview|fields|used-by|atlas`, `--data <plugins folder>`.
- **The import dialog**, with no current import: `--from-game 1` (which the game passes) ends it with Play; `--rom <path>` and `--import 1` fill it in and press Import, and a screenshot waits for the import, giving up after 15 minutes rather than one. Without `--import`, `--screenshot` saves the dialog as it opens.
- **The game:** `--checkpoint <state>` or `--save <save>` loads that game; `--play <moves>` plays a script that many moves, taking first choices, with its conversation box.
- **The UI screen** (the conversation box and the windows): `--zoom <1-3>`, `--ui-filter pixels|videoout|smooth`, `--aspect 4:3|16:9`, `--ui-lines <n>`.
- **Scenes and maps:** `--drive <request>` drives an actor; `--wireframe 1` and `--scene-camera 1` set those switches; `--collision surface|role` colours a map's collision; `--look 1` looks through a camera object's camera.
- **The Party tab and windows:** `--member <slot>`, `--list inventory|spells|skills|stats`, `--row <n>`, `--details 1`; `--roll 1` rolls a loot table or opens a container's loot window; `--press a,b,up,down` presses a window's buttons in turn, with `left` and `right` in the loot window, `cup` in a shop's and `cleft` and `cright` in a training window.
- **Screenshots:** `--wait <seconds>` waits first; `--ui-screenshot <png>` saves the UI screen too, in its own pixels.
